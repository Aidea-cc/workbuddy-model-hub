# WorkBuddy 模型中心（workbuddy-model-hub）

本地可视化配置页 + 别名网关，用来解决「多家服务商的同名模型无法在 WorkBuddy 里同时出现」的问题。

## 解决什么问题

WorkBuddy 的自定义模型把 `id` 同时当作列表去重键和请求体里的 `model`。两家服务商的真实模型名相同时，只改 `models.json` 无法同时满足「ID 不重复」和「发给上游的名字正确」。

本工具给每条渠道分配一个本地唯一名称，同时作为 `id`、`name` 和界面显示名（因此设置页、模型下拉、配置页三处一致）。请求先到本机网关，网关按渠道替换上游地址、API Key 与真实模型名，响应（含 SSE 流式）原样透传。

## 功能

- 任意 OpenAI 兼容服务商：填名称 / 地址 / 密钥 → 获取模型列表 → 勾选即自动生成渠道，工具调用、图片、推理能力自动识别
- 多服务商分组管理，同组共用一套地址与密钥；支持折叠、搜索、零定价模型隐藏
- 一键生成配置片段，备份并写入客户端 `models.json`（本机时间命名备份，保留原有条目）
- 零第三方依赖，数据存本地 SQLite；配置页支持桌面与移动端

## 运行

需要 **Node.js 22 或更高**（使用内置 `node:sqlite`），无需 `npm install`。

```bat
start.bat
```

或：

```bash
npm start
node --disable-warning=ExperimentalWarning server.js
```

启动后打开 <http://127.0.0.1:8787/>。`start.bat` 会先检测端口：服务已在运行时只打开页面，不会重复启动。

> 网关必须常驻，关闭进程后所有渠道都会连接失败。可用环境变量 `PORT`、`HOST`、`DB_PATH` 调整监听端口、绑定地址与数据库位置；默认只监听 `127.0.0.1`。

## 配置步骤

1. 点「+ 添加服务商」，填写名称、地址、API Key（本地免鉴权服务可勾选「无需密钥」）
2. 点「获取模型」并按需勾选，勾选状态自动保存、自动同步生成渠道
3. 在「导出客户端配置」设置统一显示名格式（默认 `{provider}·{modelLower}`），点「生成」
4. 填入客户端 `models.json` 的绝对路径，点「备份并写入」；写入前会自动生成 `.bak` 备份
5. 完全退出并重启客户端，即可在模型列表里看到新条目

网关地址为 `http://127.0.0.1:8787/<别名>/v1/chat/completions`，配置片段里已自动填好。

## 安全须知

- **`channels.db` 含服务商 API Key、本机路径与访问令牌，已被 `.gitignore` 排除，请勿提交、上传或分享。** 首次运行会自动创建空库。
- 服务默认只监听 `127.0.0.1`，不要把 `HOST` 设为 `0.0.0.0` 暴露到局域网。
- 「本地访问令牌」仅用于限制本机其他进程调用网关，不是上游密钥。
- 免费模型返回 429 / `Free usage limit reached` 属于上游策略限制，改用付费模型或充值即可。

## Windows 开机启动

在「运行」里输入 `shell:startup` 打开启动文件夹，放入一个 VBS 脚本即可隐藏窗口后台启动：

```vbs
Set sh = CreateObject("WScript.Shell")
sh.CurrentDirectory = "项目绝对路径"
sh.Run """项目绝对路径\start.bat"" nobrowser", 0, False
```

删除该 VBS 即可取消开机启动。不建议依赖客户端生命周期：网关需要在客户端退出或重启后仍然常驻。
