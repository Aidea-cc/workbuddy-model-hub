?使用说明与原理
  1. 点「+ 添加服务商」新增一组，填名字、地址、API Key（本地免鉴权服务可勾选「无需密钥」），点「获取模型」自动探测该服务商的模型清单。
  2. 在该组卡片里勾选需要的模型，无需点任何添加按钮：勾中的模型立刻自动生成渠道，地址、密钥、真实模型名、本地 ID 与能力开关全部自动带出；取消勾选即自动移除。换密钥只需改卡片里那一处，整组同步生效。
  3. 卡片下方的「已生成的渠道」可逐条测试连接、编辑别名与能力开关、删除；删除派生渠道等于取消该模型的勾选。
  4. 在「导出客户端配置」点「生成」，复制条目到客户端配置文件，或填绝对路径点「备份并写入」；保持本服务运行，重启客户端即可在模型列表里看到每个模型一条独立选项。
支持哪些服务商

任何暴露 OpenAI 兼容 GET /models 的 API 都可以——OpenRouter、OpenCode Zen、硅基流动、DeepSeek / 智谱 / Moonshot 官方、vLLM / Ollama / LM Studio / One-API 类自建网关等。地址可填根域名、/v1、/api/v1 或完整 /chat/completions，会自动尝试多个常见模型列表地址；接口位置特殊时在该组「高级选项」手动填即可。纯客户端（WorkBuddy、Trae 等）不提供模型列表接口，属于「导出客户端配置」的接入对象，不是这里的服务商。

为什么必须走网关

客户端把 id 原样作为请求体 model 发出，且用 id 做列表去重。两个渠道若都要求同一个模型名，纯改配置无法兼顾「都不重复」和「都发对名字」。网关把本地唯一 ID 改写成各渠道真实模型名，并换成对应地址与密钥，因此真实模型名可以相同也可以不同。

三处名称统一

WorkBuddy 设置页显示条目的 name；模型下拉在 name 与 id 不同时会拼成 name:id，两者相同时只显示一次。因此本工具让 id 与 name 完全相同，网关页面也显示同一个名字，三处都是「服务商·模型名」。写入时按网关地址认领并替换旧 ID 的条目，不会留下重复模型；末尾的「自定义」标签是客户端自己加的。

免费模型与 429

「测试连接」返回 Free usage limit reached / HTTP 429 时，是上游服务商的策略限制，不是网关故障。例如 OpenCode 官方文档明确写明「Free-tier chat models require OpenCode; use paid models or Go from other clients」，即免费层模型只供其自家客户端使用，第三方客户端需改用付费模型或订阅 Go。零定价模型默认已隐藏，取消「隐藏零定价模型」可查看；建议改用非零定价模型、给账户充值或换一家服务商。

注意

服务必须常驻，关闭后所有渠道会连接失败；服务商信息、模型清单和密钥保存在项目目录的 channels.db，备份时直接复制该文件，请勿分享（内含密钥）。能力来自上游声明或名称推断，未做真实图片请求实测，建议用「测试连接」或实际发张图确认。
